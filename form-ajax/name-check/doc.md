# 失焦查重

## 本版本引入的概念

**失焦即时校验（blur + Ajax）**：用户名是否已被占用，只有服务器知道，但不必等到提交——输入框一失焦（`blur` 事件：焦点离开那一刻）就发一次 `GET /users/名字`，答案当场标在旁边。这是 Ajax 的招牌用途：把「填完、提交、等报错、重填」的四步轮回压成「填完就知道」。

**HTTP 状态码当业务语义**：200 = 名字存在（红，已被占用）；404 = 名字不存在（绿，可以注册）。资源语义天然表达了「查无此人」，不需要另造 `{exists: true}` 的应答体。

## 本版本的改动

- 用户名输入框绑 `blur`：查重、写 tip、`classList.toggle('ok', …)` 切红绿
- tip 的 CSS 加一条 `.tip.ok { color: green }`——同一个提示位，两种脸色

## 关键代码走读

- `encodeURIComponent(name)`：用户名拼进 URL 前转义——名字里有 `?`、`#`、`/` 时它救你一命
- `if (!checkName(name)) return`：格式不对时不出声——那是提交时 validate 的职责，查重只管「格式对的名字在不在库里」，两个提示位不抢话
- 模拟层的库存在 localStorage 里（按版本隔离）：注册成功的名字，再失焦一次真的会变红；想清库重来，在运行窗口控制台敲 `__EDU_SHIM_RESET__()`
- blur 与提交查重之间没有锁：失焦查询在飞、用户手快点了提交，可能按旧答案注册——竞态是真实工程问题，本线不展开（提交后模拟层照样存得进，教学上无伤）

## 对照要点（与原课程 user_check/）

- 原课程 `user_exist.php` 返回 `'1'`/空串、jQuery `$.ajax` 的 success 里判真假——本版用状态码 + 原生 fetch，语义交给 HTTP 本身
- 原课程查重与注册是两个 PHP；本版是同一个 REST 集合 /users 的 GET 与 POST——资源只有一个，动词各司其职

## 思考题

- 改成 `input` 事件（每敲一个键查一次）会怎样？（请求量爆炸——为什么很多网站改用「防抖」：停手 300ms 才查一次）
- 两个用户同时注册同一个名字，都拿到「可以注册」，然后呢？（后一个把前一个覆盖或重复入库——又是服务端校验的理由）
