# async/await 与异步

## 本版本引入的概念

**异步不阻塞**：`await` 处代码「等」的是 Promise，页面不陪它等——事件循环把控制权还给浏览器，计时器、输入、滚动照常运转。本版用两个证据演示：等待期间计数器每秒照走、表单照打字。

**async/await**：`.then` 回调链改写成 async 函数里的顺序语句——「发送 → 等待 → 看状态 → 解析 → 显示」从右往右嵌套变成从上往下读。错误处理从 `.catch` 换成 `try/catch/finally`。

## 本版本的改动

- 监听器变 `async (event) =>`
- `wait(2000)` 模拟慢网络：原课程在服务端 `sleep(8)` 拖住应答，模拟层没有延迟，客户端自己等 2 秒（等待期间 fetch 尚未发出——原课程演示的「服务器慢」在这里折算成「网络慢」，教学效果同为「页面等得起」）
- 计数器 `setInterval` + 按钮禁用 + `finally` 收尾

## 关键代码走读

- `setInterval` 的回调在 await 的间隙里被事件循环执行——它们与 async 函数是并行的两条线，靠闭包共享 `seconds`
- `btn.disabled = true`：异步期间用户还能再点提交——重复注册就乱了。禁用按钮是异步 UI 的第一课
- `finally`：成败都得停计数器、解禁按钮。漏写 finally 是异步代码最常见的尾巴债
- 「此刻还能改表单」不是空话：提交一次，趁等待改用户名——完全来得及

## 对照要点（与原课程 form_ajax_async.htm）

- 原课程的异步演示：服务端 sleep(8)，客户端 setInterval 数到 10——教学设计原样保留，只是「慢」从服务端挪到客户端、8 秒缩成 2 秒
- 原课程 readyState 状态机每一步都可能被事件打断；async/await 把「打断后回来」的路径收进语法

## 思考题

- 把 `await wait(2000)` 删掉，计数器还会动吗？（fetch 0 秒返回，计数器刚起就被 finally 清了——「异步」得有慢才有戏）
- 为什么 `clearInterval` 放在 finally 而不是成功分支？（失败路径也要停——不然计数器永远走下去）
