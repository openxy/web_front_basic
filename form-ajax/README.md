# 表单与 Ajax（form-ajax 案例）

## 本案例教什么

表单是前端与后端交互的主通道。本案例从「没有一行 JS 的原生表单」出发，一步一步用 JS 把提交、请求、反馈接管过来，最终做出体验完整的注册页。每版接管原生行为的一环：拦下提交、发出请求、等待应答、给出反馈，每版解决上一版暴露的一个具体不足。

依原课程「实训：表单及前后端交互」原生重构：控件精简聚焦 JS，后端走 mock.json 拦截器模拟。

## 版本导览

| # | 版本 | 概念 | 解决的问题 |
| --- | --- | --- | --- |
| 01 | [传统表单](#v=form-ajax/plain) | 浏览器原生提交 | 出发点：先看清它够用在哪、不足在哪 |
| 02 | [接管表单提交](#v=form-ajax/submit) | preventDefault + FormData | 整页跳转 |
| 03 | [fetch 发送 JSON](#v=form-ajax/ajax-post) | Ajax 请求 | 必须由服务器返回整页 |
| 04 | [async/await 与异步](#v=form-ajax/async) | 异步不阻塞 | 等应答时页面卡死 |
| 05 | [提交前校验](#v=form-ajax/validate) | 行内提示 | 反馈粗糙、往返报错 |
| 06 | [失焦查重](#v=form-ajax/name-check) | 即时查询 | 填完才知道用户名是否可用 |

## 重点与边界

- 重点：原生表单行为逐环被 JS 接管的过程——每版只动一环，对照着看「接管前 vs 接管后」
- 边界：数据存哪、怎么连真实后端（REST 数据层）归 spa 案例；HTML 声明式校验属性（`required`/`pattern`）只在第 1 版作为对照提及
