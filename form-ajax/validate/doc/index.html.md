# 更新：index.html（提交前先过本地校验，新增 validate 一段）

新增三块，提交回调只头部插了一行：

- **两条规则函数**：`checkName` 正则 `/^[a-zA-Z][a-zA-Z0-9]*$/`（对应原课程服务端的 preg_match）、`checkPwd` 非空且两次一致——规则是纯函数，输入值、输出真假
- **`validate(data)`**：把「过没过 / 哪个输入框 / 提示文字」排成一张 rules 数组循环处理，提示写进各输入框旁的 `<span class="tip">`——行内红字取代原课程的 alert 弹窗，出错位置就地可见
- **提交回调开头**：`if (!validate(data)) return`——校验不过，请求根本不发出（对照原课程：数据发到服务端才被打回，一来一回全是浪费）

分工要点：规则函数管判断、validate 管呈现与汇总、提交回调只问一句「过没过」。本地校验省的是往返，但它只是体验优化——服务端校验永远不能省（绕过页面直接发请求易如反掌）。

「填错了」要到点提交才知道——把报错提前到填完那一刻，见 `name-check` 版。
