# 图片画廊（gallery 案例）

## 本案例教什么

依教程《Web前端开发技术》第 8 周《事件传播》新写（原教程「图片画廊应用」示例演化而来）。主题：动态渲染的列表怎么接行为。零依赖，图片用内联 SVG 渐变，离线可跑。

## 版本导览

| # | 版本 | 概念要点 |
| --- | --- | --- |
| 01 | [动态渲染](#v=gallery/render) | 数据拼 HTML 一次性进容器，渲染完逐个直接绑定 |
| 02 | [加载更多事故](#v=gallery/load-more-fail) | 新图点不动：直接绑定只覆盖绑定那一刻已存在的元素 |
| 03 | [事件委托修复](#v=gallery/delegation) | 监听器挪到容器一个，e.target + closest 甄别，新图天然被覆盖 |
| 04 | [模态框预览](#v=gallery/modal-preview) | e.target 区分点的是谁：点图开大图、点遮罩自身才关闭、点赞早返回 |

## 重点与边界

- 重点：直接绑定的时机死穴为什么在委托结构里「失去发生的土壤」；委托监听器必须自己甄别事件目标；甄别（closest + 早返回）与 stopPropagation 的取舍
- 边界：事故版刻意保留静默失效现场，修复在下一版；数据在内存变量，存储与服务端归 spa 案例的数据层线索
