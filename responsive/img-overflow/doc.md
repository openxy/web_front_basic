# 图片撑破容器

## 事故现场

先做后讲。运行本版，把窗口从 1000 像素慢慢拖窄：

- 容器（`.main` 的天蓝色背景）在跟着收缩，页面其余部分一切正常——流体布局尽职尽责
- 拖过大约 700 像素：图片右端探出容器边界；再拖窄，**横向滚动条回来了**

这版没有任何布局代码被改坏：样式表与上一版逐字节一致，唯一的改动是主栏多了一张 640 像素宽的配图——完全正常的编辑需求。

## 症状与根源

图片有**固有尺寸**（intrinsic size）：SVG 声明 640 像素宽，`width="640"` 又显式指定了它。容器可以缩（`max-width` 在管着），图片不肯缩——没人告诉它要缩。于是内容比容器宽，容器被撑破，整个页面跟着出横向滚动条。

这个事故的名字叫「**容器流体了，内容没跟上**」。文本天然没这个问题：文字会换行，行宽随容器伸缩；替换型内容（图片、视频、iframe）有固有尺寸，默认坚持己见。

## 本版本的改动

- 主栏两张段落后加一张配图 `<img src="pic.svg" width="640">`（内容演进，样式零改动）
- 新增 `pic.svg`：一张 640×180 的视口宽度谱系示意图

## 试试

1. 拖窄窗口，找到横向滚动条重新出现的位置——大约在视口 660 像素（图片 640 加栏宽分配余量）
2. 打开开发者工具看 `.main` 的实际宽度与图片宽度的关系：容器窄、内容宽，溢出（overflow）就此发生
3. 想一想修法再进下一版：要让「一切内容」都遵守容器的宽度上限，该把规则写给谁？（写给 `.main img` 一张张指定，还是写给 `img` 全体？）

## 思考题

- 为什么文字段落撑不破容器而图片能？
- 把图片的 `width="640"` 属性删掉，事故会消失吗？（提示：SVG 自带 640 的固有宽度）
