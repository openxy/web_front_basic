# 媒体查询断点

## 本版本引入的概念

**媒体查询（media query）**：`@media (条件)` 把一批样式圈起来，只在浏览器环境满足条件时生效。本版用的条件是 `max-width: 700px`——视口宽度至多 700 像素（窄屏形态）。于是 `.page` 有了两套列定义：

- 视口宽于 700：基础规则 `grid-template-columns: 3fr 1fr`（双栏）
- 视口 700 以内：媒体查询覆盖为 `1fr`（单栏），侧栏自然沉到主栏下方

**断点（breakpoint）**：条件里的 700 像素。窗口拖过这条线，版式瞬间切换——这是「响应式」最标志性的一刻。

注意覆盖的方向：媒体块写在基础规则**之后**，同优先级下后者胜出——窄屏时 `1fr` 赢。级联顺序在这里就是生效逻辑。

## 本版本的改动

样式表末尾追加一个 `@media (max-width:700px)` 块，内含一条 `.page` 的列定义覆盖。HTML 与上一版逐字节一致。

## 关键代码走读

```css
.page{ display:grid; grid-template-columns:3fr 1fr; … }  /* 基础：双栏 */
@media (max-width:700px){
    .page{ grid-template-columns:1fr; }                  /* 窄屏：单栏 */
}
```

先写宽屏再减到窄屏——**桌面优先（desktop-first）**，用 `max-width` 从大往小覆盖。这是响应式最初十年的主流写法：桌面版是「正本」，窄屏是「特例」。

## 试试

1. 运行后把窗口从 1000 缓慢拖到 650：过 700 的瞬间，侧栏跳到主栏下方——单栏形态
2. 左右来回拖几次，感受断点两侧的两种形态；拖动时版式是**跳变**的，不是渐变的
3. 把 700 改成 900（编辑模式），再拖：断点位置随数字走——断点是我们选的，不是浏览器给的

## 思考题

- 本版的断点选 700，依据应该是什么？（提示：不是「平板宽 768」，而是这套页面双栏形态能忍受的最窄宽度）
- 断点两侧只换了栏数，字号间距都没动——一个断点应该只改一件事吗？
