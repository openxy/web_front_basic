# 图片响应式

## 本版本引入的概念

**响应式图片的基本式**：两条声明，写给全体 `img`——

```css
img { max-width: 100%; height: auto; }
```

`max-width: 100%` 把事故版里学到的教训落成规则：图片宽度至多等于容器宽度，容器收缩图片跟随。`height: auto` 是配套：只锁宽不锁高，浏览器会按原宽高比重算高度；宽高都写死成百分比才会变形。

这两行是如此标准，以至于几乎所有响应式页面的样式表里都原样躺着——先有事故，后有疫苗。

## 本版本的改动

样式表 `body` 规则后新增 `img` 规则（两行声明）。HTML 与上一版逐字节一致——事故现场原样保留，只是从这版起它不再发生。

## 关键代码走读

规则写给 `img` 元素选择器而非 `.main img`：撑破容器的可能是任何图片，规则就写给全体。`100%` 是相对单位，参照物是包含块（containing block）的宽度——这正是上一版思考题的答案：相对单位的参照物定对了，一条规则管住全部同类内容。

## 试试

1. 拖窄窗口：图片与文字一起收缩，横向滚动条彻底消失；拖多窄都没有
2. 对照差异面板：本版与事故版的 diff 就是这两行 CSS——定位到最小修复
3. 把 `height: auto` 临时改成 `height: 180px`（编辑模式可改），拖窄窗口看图片被压扁的样子，改回来

## 思考题

- 这两条规则对本来就小于容器的图片（小图标）有副作用吗？（提示：`max-width` 是上限不是目标值）
- 视频（`<video>`）和内嵌框架（`<iframe>`）也需要这两行吗？它们的固有尺寸行为和图片一样吗？
