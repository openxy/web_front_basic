# 流体布局

## 本版本引入的概念

**流体布局（fluid layout）**：宽度不写死，改给上限。`max-width` 的语义是双向的——窗口宽于 960 时同固定宽度（版心居中、两侧留白），窗口窄于 960 时容器随之收缩，页面永远不超出视口。配合上一案例已有的比例栏宽（`3fr 1fr` 按份分配），栏宽随容器等比伸缩，这就是「流体」。

CSS 里一切长度单位都可分两类：**绝对单位**（px 写死）与**相对单位**（%、fr、em、vw 随参照物伸缩）。流体布局的改造就是逐个问：这个长度该绝对还是相对？

## 本版本的改动

`.hd,.ft` 与 `.page` 三处 `width: 960px` 全部改为 `max-width: 960px`——只改这一处声明方式，页面从「不响应」变成「随窗口伸缩」。

## 关键代码走读

```css
.hd,.ft{ max-width:960px; margin:0 auto; }
.page { max-width:960px; margin:0 auto; display:grid; grid-template-columns:3fr 1fr; gap:12px; }
```

横向滚动条的根源是「内容宽度超过视口」。`max-width` 保证容器永远不超视口，滚动条随之消失；栏宽用 `fr` 份额而非像素，容器缩了栏宽自动跟上。

## 试试

1. 运行后把窗口从 1200 拖到 500 像素：横向滚动条不再出现，页面连续收缩
2. 拖到 400 像素附近停下：两栏还在，但主栏文字每行只剩几个字，侧栏窄成一条——**会伸缩不等于好用**，这是下一组版本要解决的问题
3. 对照差异面板：本版与固定宽度版的 diff 只有 `width` 与 `max-width` 一词之差

## 思考题

- `margin: 0 auto` 居中在窗口窄于 960 时还起作用吗？（提示：此时容器已占满视口，无剩余空间可分）
- 如果只把 `.page` 改成 max-width 而页头页脚仍写死，会看到什么现象？
