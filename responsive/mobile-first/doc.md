# 移动优先

## 本版本引入的概念

**移动优先（mobile-first）**：基础样式写成最窄形态，用 `min-width` 媒体查询**向上增强**。与上一版恰好是镜像：

| | 桌面优先（上一版） | 移动优先（本版） |
| --- | --- | --- |
| 基础样式 | 双栏（桌面正本） | 单栏（最窄正本） |
| 媒体查询 | `max-width: 700px` 减到单栏 | `min-width: 700px` 增到双栏 |
| 心理预设 | 桌面是常态，窄屏是特例 | 最窄是常态，宽屏是增强 |

移动优先胜出的理由有三：手机是多数流量的起点，默认体验该是最好的那份；窄屏约束最强，内容的主次被迫想清楚，从窄往宽长比从宽往窄砍健康；增强（往上加）比降级（往下减）更不容易漏——漏写的增强最多「不够丰富」，漏写的降级是「挤成一团」。

**断点由内容定**：700 不是任何设备的宽度，是这套页面双栏形态在多窄以下开始难以阅读的实测值。设备年年换，内容宽度才是稳定依据。

## 本版本的改动

三行：`.page` 基础列定义 `3fr 1fr` 换成 `1fr`；媒体查询条件 `max-width` 换成 `min-width`；块内定义 `1fr` 换成 `3fr 1fr`。方向翻转，视觉结果与上一版完全相同。

## 试试

1. 运行并拖动窗口：两种形态、切换位置与上一版一模一样——**同样的结果，相反的书写方向**
2. 对照差异面板：本版与上一版的 diff 就是这三行的镜像互换
3. 假设要加第三个断点（比如 1100px 时侧栏加宽），在两种写法里各试加一版（编辑模式），体会哪个方向写着顺

## 思考题

- 移动优先里，媒体查询全没写时手机看到什么？桌面优先里呢？哪个更接近「没写完时不出事故」？
- 断点两侧若还要调字号（窄屏小一号），在两种写法里分别写在哪个块里？
