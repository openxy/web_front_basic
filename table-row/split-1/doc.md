# 动态事件 · 点击编辑

上一版管住了「行」的生死：一个委托监听器，能加、能删、删不错，时机问题失去了发生的土壤。但单元格里的字还是写死的——想改个名字只能删了重加。本版给数据单元格加上「点击即编辑」：td 原地变成 input，回车或点到别处就提交，空值拦下不放行。真正的课题不在编辑逻辑，而在事件：输入框在点击之前根本不存在，编辑完的 td 也是个新造的元素——绑定从「页面载入时的事」变成「元素创建时的事」。

## 本版本引入的概念

**动态绑定**：监听器不必赶在页面载入时一次挂齐，可以在元素被创建出来的那一刻再挂。`bindCellEdit` 是全部数据单元格的唯一入口，全版共三处调用：初始行载入后循环一次、新增行造好后循环一次、提交编辑重建 td 后单独一次。元素诞生，事件跟上——这就是动态事件。

**替换即失忆**：监听器长在元素身上，元素离场，监听器随之作废；新造的元素一律是白纸。`startEdit` 里 `td.replaceWith(input)`，旧 td 的点击事件随它一起退场；`commitEdit` 里 `input.replaceWith(td)`，新 td 身上一无所有。所以末尾那句 `bindCellEdit(td)` 不是补丁，是流程的一部分——省掉它，这个格子从此点不开。

## 关键代码走读（index.html）

**载入即绑**：`querySelectorAll('#list tbody td:not(:last-child)')` 挑出初始三行的数据单元格（`:not(:last-child)` 跳过放按钮的操作列），循环 `bindCellEdit`。这是全页面唯一一轮批量绑定，此后每个新元素都在诞生时自己解决。

**新增行（`#add`）**：造 tr、填 innerHTML、对数据单元格循环 `bindCellEdit`、appendChild。注意删除按钮一个监听器也没绑——上一版挂在 tbody 的委托继续罩着它。同一次新增，两种策略各干各的。

**删除（tbody 委托）**：与上一版同款：`closest('.del')` 找按钮，`closest('tr').remove()` 行删自己。逻辑一个字没动，只是把 tbody 存成变量，供新增与删除两处共用。

**bindCellEdit（td）**：`td.onclick = function () { startEdit(td); }`。闭包记住的是这个 td 本身——不是编号，不是位置。

**startEdit（td）**：造 input、拷入 `td.textContent`、`replaceWith` 原地顶替、`focus()`。紧接着给这张白纸挂两个动态事件：`onblur`（点到别处，视为提交）、`onkeydown` 里判 `e.key === 'Enter'`（回车，明确提交）。两条路都通向 commitEdit。

**commitEdit（input）**：`trim()` 后为空则提示，并用 `input.focus()` 把焦点抢回来——不填完别想走，编辑态不结束。通过则依次做三件事：造新 td 回填文本、`replaceWith` 顶替、`bindCellEdit(td)` 重挂点击编辑。末尾的重绑正是本版题眼：新 td 是白纸，不重绑就点不开。

串起来看，一次编辑的生命周期是：`td --点击--> input --回车/失焦--> 新 td`。每支箭头都是一次 replaceWith，都伴随一次旧事件死亡、新事件诞生。

## 与上一版对照：同一页面，两种策略

| | 删除（沿用上一版） | 编辑（本版新增） |
|---|---|---|
| 绑定方式 | 委托：tbody 挂一个 | 动态绑定：元素诞生时逐个挂 |
| 面对的元素 | 按钮随行增删，行永远在 tbody 里 | td 与 input 交替替换，生生灭灭 |
| 依靠的机制 | 冒泡把 click 送到 tbody | 事件直接长在元素身上 |
| 新增/重建之后 | 天然被覆盖，无需再管 | 谁创建谁绑定，漏一处坏一处 |

- 上一版收在「监听器先于一切行存在，时机问题失去发生的土壤」这句话上。本版把时机请了回来，但换了位置：不在页面载入时，而在元素诞生时。委托消灭时机问题的办法是不依赖时机，动态绑定的办法是每次都踩准它。
- 当初循环绑定的失败分支败在两处：绑得早（新增行没份）、记得错（闭包里存编号）。动态绑定逐一回应——创建时才绑，不会早；闭包记住元素本身，编号在这版同样没有出场。
- 编辑为什么不也委托？td 的点击其实可以（click 冒泡，tbody 接得住）；但 input 的失焦不行——blur 不冒泡，永远到不了 tbody。委托的边界就在冒泡：会冒泡的事件可以委托，不会冒泡的事件只能动态绑。同一页面两种策略并存的根源，是这一条。

## 思考题

- 把点击编辑也改成委托（监听器挂 tbody，用 `closest` 找数据 td）完全可行。改完后代码里哪些行会消失？input 的 `onblur` 能一并委托出去吗？`onkeydown` 呢？
- 新增行时如果忘了循环 `bindCellEdit`，新行的表现和旧行差在哪？反过来，初始三行为什么只需要绑这一次？
- 正在编辑某格时直接点同一行的「删除」，事件按什么顺序发生？打了半截的字最终去了哪里？
