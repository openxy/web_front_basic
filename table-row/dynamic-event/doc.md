# 动态事件

## 本版本引入的概念

**动态事件（动态绑定）**：监听器不必赶在页面载入时一次挂齐，可以在元素被创建出来的那一刻再挂。`changeCell` 里 `createElement` 之后紧跟 `addEventListener('blur', ...)`——元素诞生，事件跟上。

**委托的边界在冒泡**：click 会冒泡，tbody 接得住，所以删除与点击编辑都能委托；blur **不冒泡**，永远到不了 tbody，委托不了——不会冒泡的事件只能动态绑。同一页面两种策略并存的根源就是这一条。

**重生无需重绑**：提交成功后 input 换回新 td——新 td 是白纸，但它不需要绑：它的点击照旧冒泡到 tbody，被上一版的委托接住。委托把「谁创建谁绑定」的责任整个免掉了（原课程必须在生成 td 的 HTML 字符串里把 onclick 写回去，对比之下这正是委托的收成）。

## 本版本的改动

- `changeCell` 在造 input 的同时挂 `blur` 监听器（回调里用闭包直接引用这个 input）
- 新增 `updateCell(input)`：`trim()` 后非空则造新 td（带上 `class="edit"`）换回；空值则提示 + 焦点抢回

## 关键代码走读

- `() => updateCell(input)`：箭头函数闭包记住这个 input 本身——不是编号，不是位置。`updateCell` 里不需要再从事件对象取 target（两种写法等价，闭包在这里更直白）
- `input.value.trim()`：去掉首尾空白再判空——只敲空格也算空
- 空值分支的 `input.focus()`：失焦刚发生就把焦点抢回来，编辑态不结束；不填完别想走
- 新 td 的 `className = 'edit'`：换回的格子必须还是可编辑的——类标记带上，委托才认得它。忘掉这一句，这格从此点不开（试删之）
- `info.textContent`：成功路径清空、失败路径写入，红字提示区两条路共用

## 对照要点

| | 删除 / 点击编辑（委托） | 失焦提交（动态绑） |
|---|---|---|
| 事件 | click（冒泡） | blur（不冒泡） |
| 绑定位置 | tbody 一个 | 每个 input 诞生时一个 |
| 新增/重建之后 | 天然被覆盖 | 谁创建谁绑定 |
| 依靠的机制 | 冒泡把事件送上来 | 事件直接长在元素身上 |

- 至此页面三类行为各得其所：增行走页面级绑定，删除与进编辑走委托，提交走动态绑定——按事件的脾气选策略
- 编辑的生命周期闭环：`td --点击--> input --失焦--> 新 td`。两支箭头都是 replaceWith，都伴随旧事件死亡（或无需存在）、新身份登场
