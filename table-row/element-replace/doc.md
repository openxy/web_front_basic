# 元素替换

## 本版本引入的概念

**元素替换**：`replaceWith` 把一个元素从 DOM 里换下来，换上一个新元素——位置不变，身份变了。`changeCell` 把 td 换成 input，表格里从此有了「变身」。

**替换即失忆**：监听器长在元素身上，元素离场，监听器随之作废；新造的元素一律是白纸。旧 td 离场无碍（它的使命已尽）；新 input 是白纸——本版它什么事件都不需要，下一版才是它的题眼。

## 本版本的改动

- 委托监听器加第二个分支：`closest('td.edit')` 命中数据单元格则进 `changeCell`
- `addRow` 生成的数据单元格带上 `class="edit"`（可编辑标记，操作列不带）
- 新增 `changeCell(td)`：造 input、拷入 `td.textContent`、`replaceWith` 顶替、`focus()`

## 关键代码走读

- `closest('td.edit')`：选择器随手可用——类选择器限定「是 td 且带 .edit」，操作列的 td 不带 .edit 自然落空
- `input.value = td.textContent`：替换前先把原文字拷进输入框，编辑是修改不是重写（原课程的 input 是空白的，点开就丢内容）
- `input.focus()`：不聚焦的话用户得再点一下输入框才能打字，编辑体验就断了
- 生成的 input 此刻**没有任何事件**——它出现了，但还交不了差。提交是下一版的概念

## 对照要点

- 与上一版比：委托监听器从一个分支变两个分支，同一机制多管一摊；新函数 `changeCell` 是纯 DOM 操作，不含任何事件代码
- 替换与绑定的分工在本版最清楚：replaceWith 管「变身」，变身后的行为留给下一版
- 点击编辑也走委托——因为 click 会冒泡，tbody 接得住；这个事实下一版会反转一次（blur 不冒泡）
