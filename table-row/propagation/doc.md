# 事件传播三阶段

主线第二版「事件委托」吃的就是冒泡这碗饭：监听器只挂 tbody 一个，却能接到任何行里的点击——靠的是事件从被点元素沿祖先链一路向上传播。本分支把这条传播路径单独拆开看。

## 三个阶段

一次点击从发生到结束走一条固定路线：**捕获**（从 document 一路向下，到目标的父级为止）→ **目标**（target 本身，监听器按注册顺序触发）→ **冒泡**（从目标一路向上，回到 document）。`addEventListener` 的第三个参数就是选边站：`true` 在捕获阶段接，默认 `false` 在冒泡阶段接。

页面三层色块各挂了捕获与冒泡两种监听。点「内层」得到完整日志——外层捕获、中层捕获、内层目标、中层冒泡、外层冒泡，外加 document 在路径首尾各打一次卡；点「中层」路径按层级截短；点「外层」只剩目标自己。

## 与主线的关系

事件委托 = 在祖先上挂**冒泡**监听，等事件自己送上来，所以「未来新增的行」天然被覆盖——新增的行不需要监听器，只要能被点到，事件就照常冒到 tbody。反过来 `stopPropagation()` 能把这条路掐断在任何一层：掐断之后的祖先全部收不到，挂在那里的委托也就失效。主线用不到截停，但知道「传播可以停」，委托为什么成立就彻底通了。

## 试试

1. 点内层：数一数日志行数（连 document 首尾共 7 行）；再点中层、外层，对比路径长短
2. 编辑模式在中层的捕获监听里加一句 `event.stopPropagation()`：后面的路径全部消失
3. 承接上一步：截停发生在捕获阶段，委托（挂在冒泡阶段的 tbody）会受影响吗？动手验证

## 思考题

- 目标阶段为什么不分捕获与冒泡？（提示：target 的监听器按注册顺序触发，与选边无关）
- 委托监听挂得越高越好吗？把一切委托挂到 document 上，有什么代价？
