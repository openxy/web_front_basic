# 键盘事件

上一版做完了失焦提交，但键盘用户够不着「失焦」——按回车没有任何反应（原课程代码里 `//todo: 当键盘输入回车时，完成当前输入` 留的正是这个作业）。本版把它补上：一行判断，加一次主动失焦。

## 本版本引入的概念

**键盘事件**：`keydown` 在按键按下时触发，`event.key` 是按键名（`'Enter'`、`'a'`、`'Backspace'`……）。keydown 会冒泡、理论上可委托，但按键只在 input 存在的那几秒有意义、目标也永远是它自己——直接在诞生时绑，与 blur 并排，最简单。

**单一路径原则**：回车不另写一套提交逻辑，只让输入框**真正失焦一次**（`input.blur()`）——原生 blur() 派发一次真实的失焦事件，上一版挂的 blur 监听器照常接住，`updateCell` 还是那条唯一的提交路。触发路可以有很多条（点到别处、按回车），提交路只保留一条。

## 本版本的改动

- `changeCell` 造 input 时并排多挂一个 `keydown` 监听器：`event.key === 'Enter'` 则 `input.blur()`
- 提交、校验、提示一行未动——新触发路自动被旧逻辑罩住

## 关键代码走读

- `input.blur()`：不是绕过 updateCell，而是走进它。空值时按回车：blur → 空值分支 → 焦点抢回 + 红字提示，编辑继续——校验零改动
- 反面方案：在 keydown 里把提交几行再写一遍——两份提交逻辑从此各自漂移，谁也保证不了永远同步。让所有触发路汇进一个出口，这类问题失去发生的土壤
- `event.key` 是现代按键名；老代码用 `event.keyCode`（13 = 回车），数字码难读且已废弃，新代码不必再管

## 对照要点

| | 上一版（失焦提交） | 本版（回车提交） |
|---|---|---|
| 触发方式 | 点到别处 | 增加按回车 |
| 提交逻辑 | updateCell 一份 | 仍是 updateCell 一份 |
| 改动量 | — | 诞生时并排多绑一个监听器（四行） |

- 全线五版连看，事件知识到此收口：绑定（addEventListener）→ 委托（冒泡 + closest）→ 替换（replaceWith）→ 动态绑（不冒泡的事件诞生时挂）→ 键盘事件（event.key + 单一路径）。一个课程页面拆出的事件机制全景

## 思考题

- keydown 里不调 `blur()` 而是直接调 `updateCell(input)`，页面表现有差别吗？两种写法各自把「提交只有一条路」守在哪里？
- 想支持 Esc 取消编辑（换回原文字、不提交），该在哪个监听器里加分支？取消路径和提交路径该不该共用一个出口？
- 若表格有几百个格子同时开着编辑（假设），keydown 委托到 tbody 可行吗？和 blur 的差别在哪？
