# 提示项与索引偏移

## 本版本引入的概念

**提示项**：每级列表的第一项放一句「省份」「地级市」「区县」，告诉用户这一级选什么（原课程 example.html 注释里被注释掉的第二种用法，本版启用）。

**索引偏移**：提示项占据了选项 0 的位置，真实数据整体后移一格——拼索引路径时 `selectedIndex` 必须减 1。上级还停在提示项时序号算出来是 -1，键查不到，下级按空表处理（只剩提示项），行为恰好正确。

## 本版本的改动

- 构造器加可选第三参 `prompts = []`，不传时行为与上一版完全一致
- `fill` 里两处：拼键改用 `selectedIndex - offset`；填充时先 `add` 提示项（值为空串）
- 页面调用加第三参：`new PCD(pcdData, […], ['省份', '地级市', '区县'])`

## 关键代码走读

- `const offset = this.prompts.length > 0 ? 1 : 0`：原课程叫 `bIdx`，一个意思——有提示项偏 1，没有偏 0。偏移量在 fill 开头算一次，别散在循环里
- `new Option(this.prompts[v], '')`：提示项的值是空串——表单提交时「没选」与「选了」靠值区分
- 默认参数 `prompts = []`：ES6 语法，调用方少传一个参数也不报错——插件「向后兼容」的最小形态

## 对照要点（与原课程 pcd.js）

- 原课程 `if (bIdx>0) select.options[0] = new Option(...)` 按下标塞提示项；本版先 add 提示项再 add 数据，顺序即位置，不用数下标
- 原课程 `typeof(tmp) != "undefined"` 的防御，本版收敛为 `?? []` 空值合并——同一件事的现代一行

## 思考题

- 不改 fill、只在数据表头部插一个假省名，能不能当提示项？（能显示，但假省会被当成真数据去查 `"0_-1+1"`…想想键会拼成什么、下级会显示什么）
- 提示项的值若也填名字而不是空串，提交表单的人没选省会发生什么？
