# 三级级联

## 本版本引入的概念

**级联递推**：填充逻辑从「填某一级」升维成「从第 from 级填到末级」。任一级变化，从它的下一级起全部重刷：

- 省变 → `fill(1)`：市、区县全重刷
- 市变 → `fill(2)`：只重刷区县

每级的键 = `"0"` + 前面各级的选中序号依次拼接——三级键 `"0_2_1"` 就是「第 3 个省的第 2 个市」。上一版的两级规律没有变，只是被循环推广到了任意级。

## 本版本的改动

- 新增第三个下拉 `#district`
- `fillCity` 换成通用的 `fill(from)`：外层 for 走级、内层 for 拼键
- 省市各绑一个 change，起点不同（1 与 2），函数同一个

## 关键代码走读

- 内外两个 for 各司其职：外层「填哪几级」，内层「拼这一级的键」
- 换省时若只刷市不刷县（`fill(1)` 改成只填市），区县会残留上一个省的县名——级联的正确性就靠「刷到底」
- `sel(i)` 是 `(i) => document.getElementById(ids[i])` 的简写：ids 数组把「第几级」与「哪个元素」的对应关系收进数据，下一版封装时整体搬走

## 对照要点（与原课程 pcd.js）

- 原课程 `PCD.prototype.change(v)` 的 `for(v; v < pcd.ids.length; v++)` 与本版 `fill(from)` 同构——本版就是它拆掉封装后的白话形态
- 原课程以 `o.change(o.ids.indexOf(id) + 1)` 计算重刷起点（从触发者 id 反查层级）；本版在绑定时直接把起点写进箭头函数——两种「谁变了我从哪刷」的答案，后者少了运行时查表
