# scope-closure：作用域与闭包六部曲

## 本案例教什么

变量放在哪儿、谁能看见它——作用域是 JavaScript 一切封装与隔离的地基，闭包则是作用域派生出的最强工具（和最坑陷阱）。本案例用一对「计数器 + 秒表」从一次全局撞名事故演起：两个文件各自 `var count`，计数器每秒自己涨。六版走完从全局共享到文件私有的全部主流手段：IIFE 手工私有、闭包工厂、var 循环陷阱、let 一词修复、ES 模块收束。每版行为都在页面上看得见、数得出，事故与修复紧邻成对。

## 版本导览

| 版本 | 标题 | 一句话 |
| --- | --- | --- |
| 1 | [全局撞名](#v=scope-closure/global-clash) | 两个脚本各自 var count：全局一张桌，计数器每秒自涨的事故现场 |
| 2 | [IIFE 私有作用域](#v=scope-closure/iife) | 立即执行函数把变量包进文件内部，各数各的，事故消失 |
| 3 | [闭包计数器](#v=scope-closure/closure-counter) | 工厂返回的函数攥着自己的 n：外界不可直达、调用之间不失联 |
| 4 | [循环陷阱](#v=scope-closure/loop-trap) | var 循环挂三个按钮，点谁显示的都是 3——闭包捕获同一个绑定 |
| 5 | [let 一词修复](#v=scope-closure/let-fix) | var 改 let：每轮迭代独立绑定，全案最小 diff 痊愈 |
| 6 | [ES 模块作用域](#v=scope-closure/module) | type=module 文件即作用域，IIFE 退役，语言级收束 |

主线只有一条：变量可见范围从「全页共享」收窄到「谁声明谁持有」。事故成对出现——第 1 版撞名、第 4 版陷阱，各自紧邻修复版。

## 重点与边界

- 重点：全局环境的共享性、函数作用域与 IIFE、闭包的定义（函数 + 捕获的环境）与工厂用法、var 单绑定与 let 迭代绑定的差异、模块顶层作用域
- 边界：不讲词法环境与执行上下文的底层模型、不讲模块加载器演化（require/import 机制叙事在 [spa 案例](#p=spa)，从全局 script 到打包器再到 ESM）
- 配套教程：《Web 前端开发技术》第 13 章（作用域与 IIFE、闭包）——概念讲解与最小片段在教程，本案例给可跑的完整演化与两次事故现场
