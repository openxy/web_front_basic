# ES 模块作用域

## 本版本引入的概念

**文件即作用域**：`type="module"` 引入的文件，顶层声明不进全局——每个文件天然私有。第一版的全局桌子和第二版的 IIFE 补丁，都成了历史。

改动三处对应三层：counter.js 与 timer.js 拆掉 IIFE 外壳（文件本身就包着，无需再手工包一层）；两行引入加 `type="module"`；内联 script 也加 `type="module"`（内联同样享受模块作用域，里面的 `var btns` 不再进全局）。两个 count 各归各的文件，撞名在语言层面成为不可能。

模块顺带带来的另外两件事这里只点名不展开：自动严格模式；文件间显式 `import`/`export` 才互通（本例两个文件互不需要对方）。完整的模块化叙事——import/export 与加载机制的演化——在 [spa 案例的 es-modules 版](#v=spa/es-modules)，本案例只取「作用域」这一维。

## 六版收束

回看全案一条主线：撞名事故（全页共享）→ IIFE（手工私有）→ 闭包（私有加接口）→ 循环陷阱（共享绑定咬人）→ let（每轮独立绑定）→ 模块（语言级文件作用域）。变量的可见范围从「全页一张桌」一路收窄到「谁声明谁持有」——JavaScript 用十几年走完的路，六版走完。

## 本版本的改动

counter.js 与 timer.js 拆掉 IIFE 外壳（内部逻辑不动、少一层缩进，文件头注释同步一句）；index.html 三处 script 标签加 `type="module"`。let-fix 的内联循环原样保留。

## 试试

1. 运行：计数、秒表、编号按钮行为全部如常——换作用域机制，不该换行为
2. 控制台敲 `count`：未定义——两个文件各自的 count 都被文件作用域护住了
3. 与第二版并排看（差异面板）：IIFE 那层壳没了——语言把当年的仪式收编成了默认
