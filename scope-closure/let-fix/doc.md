# let 一词修复

## 本版本引入的概念

**let 的每轮独立绑定**：把上一版内联 script 里的 `var i` 改成 `let i`，一个词，事故痊愈——三个按钮各自报出 0、1、2。

机理与上一版对称：var 在循环里只有一个绑定，let 规定**每轮迭代新建一个绑定**，本轮的值固定给本轮创建的函数。三个箭头函数捕获的是三个不同的 i，各自定格在挂监听那一刻的值。上一版的思考题「要修的是绑定，不是监听逻辑」在此兑现：监听逻辑一个字没动。

顺带一个小副产品：let 的 i 不再进全局环境——控制台敲 `i` 显示「未定义」，第一版的「全局桌子」问题也被这同一个词治了一角。

## 本版本的改动

index.html 内联 script 一处：`for (var i` 改 `for (let i`。全案例最小的一版 diff——也应当是最小：修复就该一行。

## 试试

1. 运行点三个按钮：0、1、2，各归各位
2. 与上一版并排看（差异面板）：确认真的只差一个词
3. 控制台敲 `i`：未定义——let 连带退掉了全局污染

## 思考题

- let 的「每轮新绑定」像不像上一版工厂的「每次调用新环境」？（同一思想的两处实现：给数据一个不被共享的窝）
- 如果监听里要用的是循环结束后的 i，let 版还能读到吗？为什么？
