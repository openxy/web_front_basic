# 状态码与错误处理

## 本版本引入的概念

**fetch 的错误分两层，别混**：

1. **HTTP 层**：请求送到了、服务器如实作答——答 404「查无此资源」是一次**成功的 HTTP 交谈**，fetch **不抛错**，只把状态码放在 `res.status` / `res.ok`（2xx 为 true）里交给你判断。
2. **网络层**：根本没送到（断网、域名错、服务器没起）——fetch 才 reject，抛 TypeError，归 `try/catch`。

这版给 showPost 加上两层处理，页面加「查任意 id」表单：查 99 得到红字「查无此帖（404）」，不再是无声的空白或一串莫名对象。

状态码家族顺手记：**2xx** 成功（200 通用、201 已新建、204 无内容——前三版各见过一次）、**4xx** 客户端的问题（404 不存在、400 请求看不懂）、**5xx** 服务器的问题。**HTTP 状态码是唯一真相**：别用「应答体里 code: 0」另立一套。

## 本版本的改动

index.html 加「查 id」表单；app.js 的 showPost 加 res.ok 分支（红字 404）与 try/catch（网络异常），外接表单提交。列表、新建、改、删的行为不变。

## 试试

1. 查 1：正常详情；查 99：红字 404；两个都是「成功的请求」
2. 编辑模式把 API 改成 `http://localhost:9999` 再查：走 try/catch，红字网络异常——与 404 长得像，层不同
3. 删掉一条再查它的 id：404——DELETE 那版的思考题有了实测答案

## 思考题

- 为什么 fetch 把 404 当成功、把断网当失败？（各自的「谁作的答」不同）
- 400 与 404 都说「你的问题」，差别在哪？5xx 出现时客户端该重试吗？
