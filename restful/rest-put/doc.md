# PUT 全量更新

## 本版本引入的概念

**PUT = 全量替换一件资源**。地址是个体（`/posts/2`），方法换成 PUT，请求体装**替换后的完整对象**——不只改动的字段，是整个它。「改」按钮把标题加上（改）后缀，连同没动的 body、id 一起送回去，应答 200。

全量是 PUT 的语义而不只是习惯：服务器按「客户端说了算」把旧资源整个换成新的。漏送的字段不是「保持不变」，而是**被清掉**——想只改一个字段又不送全量，HTTP 另有 PATCH（局部更新），本案例不展开。

顺带一个对照记分：PUT 是**幂等**的（同一个请求发两遍，资源是同一个结果），POST 不是（连发两遍新建两条）——这是面试与设计接口时最常被问的一对。

## 本版本的改动

app.js：loadPosts 渲染列表时每条加「改」按钮——PUT 拼好的完整对象，成功后重拉列表。index.html 与上一版一字未动。

## 试试

1. 点「改」：标题加（改）后缀，列表立即重刷；连点几次后缀会叠——每次都是全量替换的新标题
2. 编辑模式把 PUT 请求体里的 `body` 字段删掉再点「改」：刷新后详情区正文没了——全量替换不给「没送的字段保留旧值」
3. 对照上一版：POST 连点两次「新建」会怎样？PUT 连点两次「改」呢？——幂等性的活体演示

## 思考题

- 为什么 PUT 必须幂等而 POST 天然不幂等？（从「重发一次丢失的请求」想：网络断了重试，哪种方法敢重试）
- 本例 id 也在请求体里，服务器以路径里的 :id 为准还是体内的为准？
