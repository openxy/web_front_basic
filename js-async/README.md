# js-async：单线程上的异步演化

## 本案例教什么

JavaScript 只有一条主线程，页面上所有事——渲染、点击响应、你的代码——都在这条线上排队。本案例用一个每 100 毫秒刷新一次的时钟当「心跳监测仪」：时钟还在走，说明主线程还能喘气。围绕一台「单线程剧场」，六版走完浏览器异步的全部主流写法：从同步长任务冻住整个页面开始，经分片让出、回调接续、Promise 链、async/await，最后到并行聚合收束。每一版都是同一个三秒级任务的重新接线，行为可对比、差异可数出来。

## 版本导览

| 版本 | 标题 | 一句话 |
| --- | --- | --- |
| 1 | [同步长任务](#v=js-async/sync-block) | 一口气忙等 3 秒：时钟冻住、按钮点不动——单线程被占满的现场 |
| 2 | [分片让出](#v=js-async/timer-yield) | 每段只忙等 50 毫秒，段间 setTimeout 让出主线程，时钟复活 |
| 3 | [回调接续](#v=js-async/callback) | 任务做完「接着做什么」交给回调函数，三连任务嵌套成金字塔 |
| 4 | [Promise 链](#v=js-async/promise) | 未来结果对象化，金字塔摊平成 then 链，错误一处 catch 收口 |
| 5 | [async/await](#v=js-async/async-await) | 同步的形状写异步：await 逐环等待，try/catch 回归 |
| 6 | [并行三连](#v=js-async/promise-all) | 互不依赖的任务 Promise.all 三路同跑，串行 3 秒的活约 1 秒完成 |

主线是**接续机制的演化**（回调 → Promise → await），不是任务本身——按钮和剧场从第 3 版起就不再变，每版换的只是「做完之后怎么接下一件事」。

## 重点与边界

- 重点：单线程与阻塞的体感、事件循环里「让出」的含义、三代接续写法的等价性与各自账单（嵌套/错误处理/可读性）、串行与并行的启动时机差异
- 边界：不讲宏任务/微任务队列的调度次序细则（那是进阶话题），不涉及 fetch/Worker 等真实异步 API——忙等任务是刻意选的「可见异步」，配合 [spa 案例](#p=spa) 的真实接口调用食用更佳
- 配套教程：《Web 前端开发技术》第 9 章（异步与阻塞、定时器、Promise）——概念讲解与最小示例在教程，本案例给完整可跑的六版演化
