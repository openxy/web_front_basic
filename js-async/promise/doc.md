# Promise 链

## 本版本引入的概念

**Promise**：把「未来的结果」做成一个对象。上一版 `compute(onDone)` 把「做完之后做什么」写成函数传进去；这版 `compute()` 什么都不收，返回一个 Promise——事情办完时它替你 `resolve()`（对外通知「完成」），接续动作全部写在 `.then()` 里。

三连任务由此摊平：每个「下一步」都是链条上的一个 `.then`，不再住进下一步的回调里。金字塔变成一条直线。

链条能依次等待的机制在 `.then(() => compute())` 这行：then 的回调**返回**一个新 Promise 时，链会等它完成再执行下一个 then——所以第二个任务的日志天然排在第一个任务之后，不需要嵌套。

## 错误处理：一处收口

上一版思考题在这里兑现。回调版要每层各写一份错误处理，因为 `try/catch` 管不到异步回调；Promise 版链条末尾一个 `.catch()` 就够了——链上任何一环抛异常，链条直接跳到 catch，中间步骤全部跳过。我们的 compute 永远成功，catch 平时不出声，但位置就是它该在的位置。

## 本版本的改动

`compute(onDone)` 改为 `compute()` 返回 `new Promise(...)`，原来调 `onDone()` 的位置改调 `resolve()`；点击处理从三层嵌套摊平成五节 then 链加末尾 catch。index.html 与上一版逐字节相同——变的只是接续机制。

## 试试

1. 运行点「三连任务」：行为与上一版完全一致（A→B→C 每约 1 秒一条）——机制换了，戏没换
2. 数一数缩进层数：一条线，五连十连都不会右移
3. 编辑模式把中间某个 `.then(() => log(...))` 改成 `.then(() => logX(...))`（故意用不存在的函数）：确认末尾 catch 接住了错误、后面的步骤全部跳过
