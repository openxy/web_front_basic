# 定时器分片

## 本版本引入的概念

**让出主线程**：单线程冻不住的解法不是多开线程，而是**长任务自己切片**——每段只忙等 50 毫秒，段与段之间用 `setTimeout(step, 0)` 把「下一段」排到任务队列队尾，主线程交还浏览器。浏览器趁间隙处理积压：时钟刷新、页面重绘、点击响应。总耗时没变（还是约 3 秒），但页面全程活着。

`setTimeout(fn, 0)` 的真实含义不是「立即」，是「尽快排上队」：回调进入任务队列，等主线程空闲才轮到它。「0 毫秒」指的是不额外延迟，排队时间另算——**代码顺序 ≠ 执行顺序**，从这版起要时刻记着这一点。

## 本版本的改动

按钮文案改「分片计算 3 秒」；点击处理改写为 `step` 递归：段内忙等 50ms，未满 3 秒则 `setTimeout(step, 0)` 让出，满了记日志收尾。

## 关键代码走读

```js
function step() {
    const segStart = Date.now();
    while (Date.now() - segStart < 50) {}    // 本段只忙等 50ms
    if (Date.now() - start < 3000) {
        setTimeout(step, 0);                 // 让出主线程，下一段排队
    } else {
        log('计算完成');
    }
}
```

50 毫秒这个数有讲究：人眼感知卡顿的门槛约 100 毫秒，一段 50ms + 一段浏览器工作，节奏刚好低于门槛。真实工程里对应的模式是「分批处理大列表」「requestIdleCallback」——思想同源：别一口气干完，干一会儿歇一会儿。

## 试试

1. 运行点按钮：时钟**全程不停**，只是任务总时长依旧是约 3 秒——阻塞没有了，等待还在
2. 计算期间选中文本、点别处：全部即时响应
3. 对照差异面板：与上一版的 diff 就是点击处理这一段——从「一口气忙等」到「分段递归」
