# 同步长任务

## 本版本引入的概念

**JavaScript 是单线程的**：同一个时刻只有一条执行流。同步代码一旦开始跑，不跑完不撒手——期间整个页面（渲染、点击、滚动）都在排队等它。这不是缺陷，是语言的设计取舍：单线程免掉了并发改同一份数据的种种麻烦，代价是**任何一段长任务都会冻住整个页面**。

这版就是这个事故的现场：页面上一枚每 100 毫秒刷新的时钟（心跳监测仪）+ 一个忙等 3 秒的同步计算按钮。点下按钮，3 秒内时钟停摆、按钮卡死、页面纹丝不动——「阻塞」二字的最佳注解。

## 本版本的改动

一切从零搭起：index.html（时钟、按钮、日志列表）+ app.js（时钟的 setInterval、按钮的同步忙等循环）。

## 关键代码走读

```js
const start = Date.now();
while (Date.now() - start < 3000) {}   // 忙等：什么都不做地占着主线程
log('计算完成');
```

`while` 循环体是空的——它不计算任何东西，唯一的作用是**占着主线程不放**。这 3 秒里：setInterval 的回调在任务队列里排队（到不了主线程）、浏览器想重绘页面也排不上、你的点击同样没回应。真实世界里的对应物：解码大图片、同步 XHR、深递归计算。

## 试试

1. 运行，先看时钟正常走动
2. 点「同步计算 3 秒」：时钟立刻停摆，3 秒后跳到当前时间继续走——停掉的 3 秒就是主线程被占用的时间
3. 计算期间反复点按钮、选中文本：都没反应；3 秒结束后，排队期间的点击会不会补触发？观察日志验证你的判断
