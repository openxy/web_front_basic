# 登录态显示与退出

## 本版本引入的概念

上一版 cookie 里已经有了登录态，但界面上看不出来——导航里永远是一个「登录」链接。本版让界面跟着状态走：**导航读 cookie 分支渲染**，退出登录随之兑现。

三拍：

+ **是什么**：登录态显示是同一份站点模板的两种形状——cookie 里有人，导航尾端亮「当前用户：admin · 退出登录」；没人，就是一条「登录」链接。退出登录没有神秘之处：把 cookie 删掉（`clearCookie`，`max-age=0` 即过期）再刷新界面
+ **怎么兑现**：`siteNav` 开头 `getCookie('user')` 读一次，三元表达式选一个导航项；页面每次载入模板都重新读——登录跳转、退出跳转都是整页加载，导航天然反映最新状态，不需要监听什么「登录事件」。退出链接走 `login.html?logout=1`，登录页开头见参数即删 cookie
+ **为什么**：UI 是状态的函数，状态住在 cookie 里；谁渲染模板谁读状态。v9 的「改状态 → 重渲染」在这里换个面孔重现——状态在 cookie，渲染在每次整页加载时发生。静态站点没有「原地变」的能力，这层局限要到真实前端框架（响应式状态）才解除

## 与上一版的 diff

`lib/auth.js` 补 `clearCookie`；`lib/view.js` 的 `siteNav` 拿掉静态「登录」项，换成读 cookie 的三元分支（`authItem`）；`login.html` 开头两行处理 `?logout=1`。其余不动。

## 观察

+ 登录后回任何前台页：导航尾端是「当前用户：admin · 退出登录」
+ 点「退出登录」：落到登录页，cookie 已删（F12 → 应用 → Cookies 查看）；再回前台，导航回到「登录」
+ 退出后硬闯后台：门禁（上一版）照样拦下——显示与门禁读的是同一颗 cookie

## 思考

+ 「当前用户：admin」是脚本读 cookie 拼出来的，学生在控制台改 cookie 再刷新，界面就认——身份显示与身份校验都依赖客户端可改的数据，呼应上一版「客户端状态不可信」
+ 为什么退出后界面不用写代码去「更新导航」？（退出链接本身造成整页跳转，新页面渲染时 cookie 已经没了）
