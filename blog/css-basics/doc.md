# 全站样式

## 本版本引入的概念

结构与样式分离的第一次兑现：HTML 一行没动（逐字节与上一版相同，可自行对照），新增一份共享的 `assets/css/style.css`，每个页面只在 `<head>` 里多一行 `<link>`。

三拍看 CSS：

+ **是什么**：规则式指令——一条规则 = 选择器（对谁）+ 声明块（改什么）。浏览器把选择器在文档树里匹配一遍，样式就上了身。这不是一步步执行的命令，是一组「满足条件即生效」的声明
+ **怎么兑现**：`<link>` 把样式表拉进来，浏览器解析成规则表，渲染每个元素时按选择器匹配、按层叠与继承定值——所以 `.post` 这一条规则同时管住了八个页面上所有卡片，一处修改全站生效
+ **为什么**：v1 埋的钩子此刻兑现——`.pinned` 卡片高亮、`.site-header a.active` 高亮导航当前项。样式层拿 class 当接口，结构与外观各改各的，这正是「结构/样式/行为分离」的成本收益所在

覆盖的入门面：元素/类/后代选择器、颜色与字体、盒子模型（`margin/border/padding`、圆角）、`display: flex` 先在导航上小试（v5 才正式讲布局）。诗词排版给了排版一个典型场景：`.poem-body` 居中放大行距——同样的规则，散文页不适用，这正是「按内容类型分样式」的雏形。

## 与上一版的 diff

新增 `assets/css/style.css`；13 个页面各加一行 `<link>`。没有别的。

## 观察

- 首页：置顶两篇带黄底「置顶」标记，卡片有了圆角与留白
- 任一详情页：诗行居中、题解底色成块、评论表单成了「能看」的样子
- 改 `style.css` 里 `.post` 的背景色再刷新：八个页面的卡片一起变——单一样式源的力量

## 思考

+ 为什么不把样式写在每个 HTML 的 `<style>` 里？共享一份 `style.css` 省了什么、多背了什么（一次额外请求）？
+ `mark` 标签自带黄底——v4 又给它写了样式，语义标签的默认样式和自定义样式是什么关系？
