# 单页应用

## 本版本引入的概念

十几个 HTML 文件并成一个：`index.html` 只剩空壳与三行 `<script>`，页面切换交给 **hash 路由**。全站 URL 收敛为最后形态：

```
#/              #/posts        #/posts/1       #/posts/new
#/posts/1/edit  #/tags         #/about         #/sitemap
#/admin/posts   #/admin/comments  #/login
```

三拍：

+ **是什么**：SPA 的「单页」指浏览器只加载一个 HTML；页面切换 = 改 `location.hash`，路由器监听 `hashchange`，在**一张路由表**（`ROUTES`）里查表：路径正则命中哪条，就调哪个视图函数。视图函数与 v12 的页面脚本一脉相承——取数、调模板、上屏，只是从「一页一个文件」变成「一路由一个函数」
+ **怎么兑现**：hash（`#` 后的部分）变了不触发页面刷新——浏览器把 `#` 视为页内锚点，只派发 `hashchange` 事件。路由器接住它重渲整页。于是「刷新/前进/后退/分享链接」这些浏览器原生能力全部免费获得：任何视图的 URL 都可收藏、可直开（直开时 `route()` 按当前 hash 恢复现场）——v9 思考题「状态可分享怎么办」在此收束
+ **为什么**：URL 即状态。多页站里 URL 由文件路径充当；SPA 里没有文件了，路由表接棒成为 **URL 布局的单一事实源**——站点地图页（`#/sitemap`）不再手写，直接由 `ROUTES` 生成，一份数据两处兑现，布局再变地图也不会说谎

对照案例集：hash 路由的机制细节（为什么用 hash 而不用 history API、路由并发与滚动位）见 spa 案例的 `router` 版；本版重点在「前后台一个站」的整体合体：前台（访客）与后台（站长）共用一张路由表、一个数据层、一套模板库。

## 与上一版的 diff

新增 `lib/router.js`；`index.html` 变空壳；删除 `posts/`、`tags/`、`admin/`、`about.html`、`sitemap.html` 共 13 个文件（视图函数收编进路由表）；`lib/view.js` 的站内链接全部改 hash 形态。

## 观察

- 点导航、翻页、进后台：地址栏的 `#…` 一直在变，页面从不整页刷新（Network 面板里没有新的文档请求）
- 复制 `#/posts/6` 到新标签页：直接落在《酬乐天》——URL 即状态
- 后台新建诗文保存：跳回 `#/admin/posts`，列表已含新篇；再点它的标题，前台详情页立即可见
- `#/sitemap`：全站路由一页看全，它由路由表生成
- 登录也是一条路由：`#/login` 登录成功进 `#/admin/posts`，导航亮出「当前用户 · 退出登录」；退出链接带 `?logout=1` 回到登录页。未登录硬闯 `#/admin/posts`，门禁在渲染前就把 hash 改回 `#/login`——此时控制台会有一条 `addEventListener` 报错：视图被门禁送走后，页面脚本后半段还要找那些没渲染出来的元素。页面行为不受影响，报错源于「门禁先送走页面、脚本后半段照常执行」的时序，不必修
