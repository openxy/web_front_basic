# 页面模板

## 本版本引入的概念

上一版各页面的内联脚本里有大量重复：导航、侧栏、卡片、详情模板散在四个文件里。这一版把它们收拢成 **`lib/view.js` 页面模板库**，页面文件瘦成壳。

**页面模板的两层**（对应设计里的站点模板与内容模板）：

+ **站点模板**：`siteNav` / `siteSidebar` / `renderPage`——站点头、主导航、分类侧栏、站点底这些全站共享的「背景框」。`renderPage(ROOT, active, mainHtml)` 一个函数把整页拼装起来，`active` 参数标出当前导航项，侧栏分类计数从 `DATA` 现算（v5 手写计数的债清掉了）
+ **内容模板**：`renderPostCard`（首页卡片）、`renderPostRow`（列表行）、`renderPostFull`（诗文详情）——同一内容类型的页面共享的「前景窗口」

**页面实例 = 站点模板 + 内容模板 + 动态内容**，这条公式落到代码就是：每个页面脚本只做三件事——取数（`DATA` 与查询参数）、调模板拼出主内容、交给 `renderPage` 上屏。

三拍：

+ **是什么**：模板即函数——输入数据，输出 HTML 字符串。没有魔法，就是普通 JavaScript 函数
+ **怎么兑现**：脚本从上到下执行，模板函数被调用时字符串拼接才发生；`renderPage` 一句 `innerHTML` 整页重写
+ **为什么**：模板概念先于模板引擎。ejs 那类前端模板引擎（见 spa 案例 `template` 版）只是把「函数拼字符串」换成了「写得更像 HTML 的模板语法」——引擎换了，两层模板的划分不变

## 与上一版的 diff

新增 `lib/view.js`；四个页面的内联函数搬走、脚本瘦身。渲染产出的 HTML 与上一版逐字节相同——重构只动「代码组织」，不动「渲染结果」。
