# 响应式

## 本版本引入的概念

同一页面在不同宽度的屏幕上都好看：**媒体查询**。本版全部改动就是 8 行 CSS——HTML 与上一版逐字节相同，可自行左右对照，这是「样式层独立演化」的又一次实证。

三拍：

+ **是什么**：`@media (max-width: 720px) { … }` = 「视口不宽于 720px 时，这批规则生效」。条件满足才启用的规则集，覆盖（而非替换）桌面样式
+ **怎么兑现**：浏览器每帧渲染前都知道当前视口宽度，媒体条件变了就重算匹配的规则集——没有 JS 参与，样式层自己闭环
+ **为什么**：两栏格子 `grid-template-columns: 1fr` 折叠成单列、侧栏 `order: 2` 挪到正文之后、导航 `flex-wrap` 允许换行——内容一个字节不改，只换排布指令。结构/样式分离的价值在这里最直观

配图（`max-width: 100%`，v4 已写）在窄屏自动缩宽，响应式的图片纪律提前埋好了。

## 与上一版的 diff

`style.css` 追加一段 `@media`，其余文件零改动。

## 观察

- 把浏览器窗口拖窄过 720px：两栏叠成一栏，侧栏移到正文后面
- 拖回宽屏：两栏恢复，全程无刷新无脚本

## 思考

+ 手机优先（先写窄屏样式，宽屏用 `min-width` 增强）与桌面优先（本版写法）各有什么心智负担？
+ 如果侧栏在手机上是最重要的入口，「挪到后面」还成立吗？——响应式不只是缩放，还是内容优先级的重排
