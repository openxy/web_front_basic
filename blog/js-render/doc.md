# 数据与渲染

## 本版本引入的概念

内容搬进 JS：诗文与评论写进 `lib/data.js`（全局变量 `DATA`），首页、列表页、标签页、详情页全部改由脚本**程序化驱动**渲染——静态 HTML 只留下区块外壳和一个容器元素。

页面实例随之坍缩：8 个 `posts/show-N.html` 并成一个 `posts/show.html`——**页面实例 = 模板 + 数据**的第一课。URL 里 `?id=1` 指定实例，脚本用 `URLSearchParams` 读参数、`find` 取数据、模板字符串拼 HTML、`innerHTML` 上树。这个四步就是前端渲染的最小闭环。

三拍：

+ **是什么**：数据（`DATA`）与视图（页面模板）分离。改一首诗的注释只动 `data.js`，页面代码不碰
+ **怎么兑现**：脚本在页面加载后同步执行（`<script>` 放在容器之后），拼好的 HTML 字符串塞进容器——此刻是整段重渲，没有增量更新
+ **为什么**：v5 留下的问题（侧栏分类数、13 份重复的页面骨架）在数据视角下有了统一解法：数据只有一份，重复的部分交给代码生成。代价也在此立此存照——JS 不跑，页面是空的；搜索引擎与无 JS 环境看到的只有外壳（这是后来组件框架与 SSR 要解决的老大难，先记下）

URL 布局跟着变：`show-N.html` 退役，`show.html?id=N` 上岗，`sitemap.html` 同步更新——URL 也是演进的活文档。

## 观察

- 从列表页点「乌衣巷」：地址栏 `show.html?id=5`，页面由脚本现场拼出
- 把 `?id=5` 改成 `?id=99`：得到「诗文不存在」——数据驱动的页面第一次有了对错误参数的回应
- 查看 `lib/data.js`：诗文的题解、注释、出处都在这一个文件里
