# 多页成型

## 本版本引入的概念

站点从一页长成一个站：**页面规划**。首页之外补齐四类页面——诗文列表（`posts.html`）、诗文详情（`post-1.html`…每篇一个文件）、标签（`tags.html`）、关于（`about.html`），导航从此可点，页面之间靠**相对链接**互跳。

三拍看这一版：

+ **是什么**：一个站点 = 一组页面 = 一组 URL。此刻的 URL 是反面初稿：全部平铺在根目录，详情页叫 `post-1.html`、`post-2.html`……文件多了就乱
+ **怎么兑现**：浏览器按 `href` 里的相对路径找文件。`post-1.html` 与 `index.html` 同级所以直接写名字——下一版目录一变，这些链接全要跟着改，URL 与文件布局的耦合此刻暴露得最彻底
+ **为什么**：详情页「每篇一个文件」正是资源式 URL（`posts/show-1.html`）的史前形态——先把「一类内容有 N 个实例、每个实例一个页面」这件事做出来，下一版才知道要把它们归到哪去

顺带入场的还有**表单控件**：每篇详情页底部有评论表单（`input`、`textarea`、`button`、`fieldset`），`required` 让浏览器原生校验先顶上。此刻提交没有去处（`action="#"`），接口要到 v12 才兑现——先把界面画全，是资源设计的惯例。

## 与上一版的 diff

`index.html` 长出导航链接；新增 12 个页面文件。没有任何样式，纯结构。

## 观察

- 从首页点进任一篇详情页：诗行、题解、注释、评论表单都在
- 故意把一篇详情页改名再点它：浏览器 404——相对链接是「按名索骥」

## 思考

+ 十篇诗文、十个 `post-N.html`，再加「改一处导航要改十个文件」——重复到第几处你会想找办法？
+ 表单提交后数据去了哪里？此刻的答案是「 nowhere」——那 `required` 校验的是给谁看的？
