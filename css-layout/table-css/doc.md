# 表格特性回归样式层

## 本版本引入的概念

**display:table**：CSS 成熟后，表格布局的**视觉特性**（等高列、垂直居中）被收回样式层——`.page { display:table }` 让普通 div 当表格，`.main/.side { display:table-cell }` 当单元格，等高列照送，而 HTML 里全是语义干净的 div。

上一版的「禁止表格布局」到这里才说得完整：被废弃的是拿 table **语义标记**做布局；表格布局的**特性**本身没有死，它以 `display:table` 的身份活在 CSS 里，需要的场合（比如天然等高列）照用不误。

## 本版本的改动

- HTML：`<table>/<tr>/<td>` 全部换成 div——**从本版起直到第 7 版，这份 HTML 一字不改**，后面五版只动样式；「布局与结构分离」第一次成为事实
- 页头、页脚移出表格成为独立块（`.hd,.ft { width:600px; margin:0 auto }` 自己居中），只有需要等高列的主体两栏留在 `.page` 表格里
- `.page` 加 `display:table`，`.main/.side` 加 `display:table-cell; vertical-align:top`

## 关键代码走读

- 等高列回来了，且语义干净：侧栏背景一直铺到与主栏齐平——对比下一版浮动栏的参差
- 两栏之间**没有间隙**：table-cell 的间距要靠 `border-spacing`，但它会在容器外沿也加缝，拼 gutter 很别扭——栏间距这个观察点，本版的答案是「忍着」
- `display:table` 的宽度行为像真表格：内容与声明宽度协商，不完全受 `width` 控制（shrink-to-fit 倾向），这是它偶尔不如人意的地方

## 试试

- 把 `.page` 的 `display:table` 删掉：两栏变回块级 div 各占一行的默认流——布局能力整个来自这一行声明，结构本身不提供任何布局
- 给 `.page` 加 `border-spacing:12px`：栏间距有了，但页面外沿也多了一圈缝

## 思考题

- display:table 与 `<table>` 标记，渲染结果几乎一样，为什么后者被禁、前者合法？（语义在读屏与爬虫眼里，标记名就是语义；样式怎么摆不关语义的事）
- display:table 这么好用，为什么没能成为主流布局方案？（提示：它只是回收了表格的旧能力，对齐、分布、弹性这些新需求它一样没有——正是后两版的主题）
