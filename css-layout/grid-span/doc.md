# 跨格落位与整页网格

## 本版本引入的概念

**格线跨格落位**：grid 的子元素可以声明自己占据的**格线范围**——布局不再是「顺着流排」而是「在网格上落位」：

- `.hd,.ft { grid-column:1/3 }`：从第 1 条列格线到第 3 条——横跨全部两列（`3fr 1fr` 两条轨道，格线有 3 条）
- `.side { grid-column:2; grid-row:2/4 }`：钉在第 2 列、纵跨第 2 至 3 行——与左列的主栏、相关阅读同高

于是页头、主体两栏、相关阅读、页脚**整页一张网格**：`.page` 的两条轨道管宽度分配，`gap` 的行列两个方向管所有间距，跨格声明管骨架结构。这是 960 栅格「在坐标纸上落位」理念的完全体——只不过坐标纸如今是语言原生能力。

页头内部仍是第 5 版的 flex：**grid 搭骨架、flex 排行内**，一维二维组合使用是现代布局的常态。

## 本版本的改动

- 页头、页脚从 `.page` 外挪进 `.page` 内：整页成为一张网格（结构六代以来第一次动——为的正是让「页面骨架」本身成为 grid 的演示场）
- 主栏下新增「相关阅读」块：左列从一栏变两段，侧栏纵跨才有的可跨
- `.side` 加 `grid-column:2; grid-row:2/4`，`.hd/.ft` 挂 `grid-column:1/3`
- 页头页脚原 `.hd,.ft` 的居中声明删掉：网格子项默认拉伸填满轨道，宽度与间距全由网格接管

## 关键代码走读

- 格线编号从 1 数起、从左往右（列）/从上往下（行），还可以倒数：`-1` 是最后一条——`grid-column:1/-1` 永远表示「横跨全部列」，轨道数变了声明不用改
- `.side` 的落位是**显式**的（列与行都指定），`.main/.extra` 是**自动**的（顺着空格流排）——显式格子先占位，自动子项绕开它们填空，本页顺序 main → side → extra 即自动落位的结果
- gap 此刻同时管行距与列距：页头与主体之间那条 12px 的缝，第 2 版到第 6 版都要单独处理，现在免费

## 试试

- 把 `.side` 的 `grid-row:2/4` 改成 `2/3`：侧栏只占一行，第 3 行右列空出一个洞——自动子项不会替它补位，落位是声明出来的
- 给 `.ft` 也加 `grid-row:4`：显式落位页脚；再故意写 `grid-row:3`——与纵跨的侧栏撞车，浏览器会把页脚推到新行
- 命名区域（`grid-template-areas`）能用名字画出布局草图，见延伸指南

## 三代布局技术对比（收束）

| 特征 | 浮动（第 3–4 版） | Flex（第 5–6 版） | CSS Grid（第 7–8 版） |
| --- | --- | --- | --- |
| 模型 | 脱离文档流的拼装 | 一对轴线（一维） | 行列轨道（二维） |
| 典型场景 | （历史）多栏、环绕 | 导航条、工具栏、行内弹性分配 | 页面骨架、卡片矩阵、仪表盘 |
| 上手成本 | 补丁与禁忌多（clearfix、百分比心算） | 低 | 低到中（格线概念需一次到位） |

选型经验：**一维用 Flex，二维用 Grid；不确定就先 Grid 搭骨架、Flex 排行内**。

八版回望：表格布局（语义污染）→ display:table（特性回归但能力旧）→ 浮动多栏（细节繁琐）→ 960 栅格（声明式但写死）→ flex（一维弹性）→ grid（二维原生）——每一种新方案都是对前一种缺陷的回答；而第 2 版到第 7 版 HTML 一字未动，本身就是「布局与结构分离」的演化史。
