# 子项弹性分配

## 本版本引入的概念

**子项的 flex 属性**：上一版轴线是容器的能力，这一版「弹性」二字正式到位——子元素用 `flex` 声明自己**如何分剩余空间**：`.main { flex:3 }`、`.side { flex:1 }`，两栏按 3:1 比例瓜分容器宽度，永远填满一行。`flex:3` 是 `flex-grow:3` 的简写（还有 shrink 收缩、basis 基准两个分量）。

对比浮动时代与 960 时代的宽度方案，才知道这两行有多轻：

- 浮动版：68% 还是 28%？人肉算，算完还得防边框超宽
- 960 版：占几列？查预计算表，620px 写死，页面锁 960px
- flex 版：3 份对 1 份，比例天然成立，宽度天然弹性——拖动窗口，两栏按比例伸缩

## 本版本的改动

- `.page` 挂回独一的类名（`container_12` 退场）：`display:flex` 接管横排，宽度 960px 改成 `max-width:960px`——大屏封顶、小屏收窄，页面第一次随窗口伸缩（`.hd/.ft` 同步改 `max-width`）
- `.main/.side` 摘掉 `grid_8/grid_4`，各写一行 `flex:3` / `flex:1`
- **clearfix 整块删除**：flex 布局没有浮动，父元素高度从不塌陷——实行了三版的「税」不用再交，这就是删除即教学的时刻
- 栏间距用 `.main { margin-right:12px }` 拼：flex 当年还没有 gap，留个伏笔给第 7 版

## 关键代码走读

- 等高列悄悄回归：flex 子项默认 `align-items:stretch`，侧栏的 wheat 背景又铺到与主栏齐平了——第 2 版 table-cell 的遗产、第 3 版丢掉的能力，在 flex 里免费回来
- `flex:3` 分的是**剩余空间**而非全宽：内容太挤时盒子不会小于内容最小宽（可 `flex-shrink` 调）
- 页头上一版的 `justify-content/align-items` 原样工作——容器轴线与子项分配是两层正交的能力，本版只加后者

## 试试

- 拖动窗口宽度：两栏按 3:1 伸缩、恒填满一行——浮动版与 960 版做得到吗？
- 把 `.side` 改成 `flex:2`：比例变 3:2；再给 `.side` 加 `max-width:260px`——侧栏到顶就不长了，弹性与上限可以叠加
- 删掉 `.main` 的 `margin-right`：两栏贴住——flex 的 gap 要到下一版 grid 才成为布局原语（较新浏览器 flex 也支持 gap，历史脉络按 grid 讲）

## 思考题

- 圣杯布局（页头 + 主侧栏 + 页脚，短内容页脚仍贴屏幕底）用 flex 怎么搭？（提示：`body` 设 `min-height:100vh; display:flex; flex-direction:column`，中段容器 `flex:1`——两版概念合起来就够）
- 960 栅格的类名约定（`grid_8`）与 flex 的份数声明（`flex:3`），都是「声明式布局」，差别在哪？（前者份额是**预计算的死数**，须整套样式包配合；后者是**运行时按份分**，容器多宽都成立）
