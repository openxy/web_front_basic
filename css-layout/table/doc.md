# 表格布局

## 本版本引入的概念

**表格布局**：Web 古早时代 CSS 尚未成熟，最现成的多行多列结构是表格，于是它被借去干布局的活。本版用 `<table>` 拼出页面骨架——页头横跨、主栏侧栏两列、页脚收尾，且同一行的单元格自动等高：侧栏文字比主栏短，却天然与主栏一样高。

问题出在「表格」一词的两层含义被混用：作为**语义**，它表示一组关系型数据（表格的本职）；作为**视觉布局**，它表示多行多列的排列样式。拿语义标记做视觉呈现，复杂布局就得表格套表格，HTML 里堆满语义无关的标记，爬虫和读屏苦不堪言——现代规范因此**禁止用 table 标记做布局**。

> 本案例（css-layout）依《Web 前端开发技术·06 前现代布局 / 弹性盒子布局 / 栅格盒子布局》三篇新写（原课程目录无对应文件）：八代版本实现同一个页面骨架，走完「表格 → display:table → 浮动 → 960 栅格 → flex → grid」的布局演化史。浮动本身（文字环绕、高度塌陷、清除）的机理在 position 案例的浮动四部曲，本案例聚焦它被挪用做**布局**的这条线。

## 本版本的改动

- 全新起点版：`<table class="page">` 三行拼骨架——页头 `colspan="2"` 横跨两列、主栏 70% + 侧栏 30%、页脚再横跨
- `border-collapse:collapse` 去掉单元格默认间隙，页头与主体才严丝合缝
- `.page td { vertical-align:top }`：单元格内容默认垂直居中，页面排版习惯是顶部对齐

## 关键代码走读

- 等高列免费送：表格同一行的单元格高度一致，不需要任何额外声明——这是表格布局留给后世的遗产（第 2 版马上回收）
- 布局信息一半在 HTML 结构里（tr/td/colspan）、一半在样式里（td 的宽度）：改布局要动结构，这就是「语义污染」的具体长相
- 页头里的 MySite、菜单、登录此刻只能行内顺排贴左——想让 Logo 靠左、登录靠右、整行垂直置中？表格时代没有工具，这个悬念留到第 5 版

## 试试

- 把 `.side` 的宽度改成 10%：整行重新分配，但你得在 HTML 里逐个数 td 才能确认改的是谁
- 想象（或用读屏软件）听这个页面：「表格，一行，单元格，单元格……」——语义污染不是比喻，是读屏用户与爬虫的日常
