# 浮动多栏

## 本版本引入的概念

**浮动多栏**：浮动的最初用途是文字环绕图片（见 position 案例浮动版），古人发现了另一个用途——块元素浮动后不再独占一行，会横向排排站。让各栏全部浮动、宽度用百分比，就是当年最主流的布局法：`.main { float:left; width:68% }`、`.side { float:right; width:28% }`，剩下的 4% 就是栏间距。

代价清单也从此背上了：

- **高度塌陷**：全部子元素漂走后，父元素高度失去依据（塌为 0），页脚会撞上来——所以 `.page::after` 那条 clearfix 必须兜底（事故现场与清除机理在 position 案例浮动四部曲，此处只引用结论）
- **等高列没了**：对比上一版，侧栏的 wheat 背景只铺到自己内容的底部，不再与主栏齐平——等高在浮动时代是靠背景图假栏等杂技硬凑的名题
- **百分比要人肉算**：68% 加 28% 加边框会不会超宽？加 padding 呢？每个数都要心算验证

## 本版本的改动

- `.main/.side`：`display:table-cell` 换成 `float`，宽度 70%/30% 调成 68%/28%（留 4% 当栏间距）
- `.page`：撤掉 `display:table`，新增 `.page::after` 的 clearfix 块——HTML 一行未动，这是第 2 版定下的骨架

## 关键代码走读

- `float:left` 配 `float:right`：两栏各自贴边，中间自然留白——栏间距观察点的本版答案「用剩余百分比当缝」
- clearfix 四行是浮动布局的**税**：只要用浮动做布局就得交，且忘了交必出事故
- 宽度是死的：窗口拉宽，600px 的页面不动——弹性无从谈起（第 6 版解决）

## 试试

- 把 `.page::after` 整块注释掉：页脚立刻撞进两栏之间——高度塌陷的一眼现场，胜过千言万语
- 把 `.side` 的宽度改成 38%：两栏宽度之和超了 100%，右栏被挤到下一行——百分比布局的脆弱

## 思考题

- 上一版等高列是免费的，这一版为什么要费这么大劲？（table-cell 的等高来自表格渲染模型；浮动元素只是脱离文档流的块盒，各长各的）
- 浮动布局撑起了 Web 的少年时代，但它本是干别的活的——这个「挪用」与第 1 版拿表格做布局有何异同？（都是借用现成机制；区别在浮动至少是样式层手段，没污染 HTML 语义）
