# 栅格系统 960

## 本版本引入的概念

**栅格系统**：浮动布局还有一个深层缺陷——实现细节太多，不利于**共享**。设计行业早有答案：坐标纸上打满栅格，设计师无需尺子就能对齐边界。960.css 把它搬进 Web：**预先约定 12 条等宽的列和列间距，布局变成「占几列」的声明**——元素挂上约定好的类名，立刻获得对应宽度。

它确立的概念词汇沿用至今：

- **container**：包裹整个栅格系统的容器（`.container_12`，960px）
- **column**：一列（12 列体系下每列 60px）
- **gutter**：列与列之间的空隙（20px，由左右各 10px 的 margin 拼成）

算式：`960px = 10 + 60×12 + 20×11 + 10`（两侧补白各 10px）。实现原理朴素得惊人——把每种「占 N 列」的宽度**预先算好写死成类**（本页只用到 grid_8/grid_4，故只写这两条），底层正是上一版的 float。

## 本版本的改动

- 页面拓宽到 960px：`.hd/.ft` 与容器都从 600px 改为 960px（960 体系是固定宽度，这是它的招牌也是死穴）
- `.page` 挂上 `container_12`，主栏挂 `grid_8`、侧栏挂 `grid_4`（8 + 4 = 12 列，主侧比约 2:1）
- 样式里 `.main/.side` 只剩皮肤（背景色）：宽度与浮动全部移交 `.container_12 .grid_N` 预计算块——**布局约定与自身样式分离**，bootstrap 的 `.row/.col-md-6` 同一思路
- clearfix 原样保留：底层还是浮动，税照交

## 关键代码走读

- `class="main grid_8"`：两个类名各司其职——`.main` 是「这是什么」（皮肤），`.grid_8` 是「占几列」（布局）；写页面的人从此只声明占位，不算像素
- `margin-left:10px; margin-right:10px`：gutter 不是容器给的，是每个格子左右各带 10px——12 列的缝隙就是这么拼出来的
- 写死的 620px/300px：换 12 栏布局要改类不算难，但**页面永远 960px**——手机上这页只能横向滚动

## 试试

- 把 `grid_4` 改成 `grid_5`（同时在预计算块加一条 `.grid_5`，宽 60×5+20×4=380px）：主侧比例变了，但没换实现思路——这就是声明式的含义
- 把窗口缩到 960px 以下：页面纹丝不动、出现横向滚动条——「固定宽度、不支持响应式」正是 960.css 的缺陷清单，也是下一代的需求清单

## 思考题

- 栅格系统与 CSS Grid 是一回事吗？（栅格是**设计理念**，960.css 用 float 实现它，bootstrap 用 flex，CSS Grid 把它做进语言本身——第 7 版见）
- `.main.grid_8` 里为什么布局类和皮肤类要分开？（约定类名是共享词汇，混进站点私有样式就没法复用了）
